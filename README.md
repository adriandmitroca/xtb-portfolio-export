# Portfolio Export for XTB

_Unofficial — not affiliated with, endorsed by, or connected to XTB. "XTB" is
used only to describe what the tool works with._

Export your **XTB** portfolio (from the xStation web app) — open positions, P/L,
IKE, IKZE, Investment Plans and regular single purchases (My Transactions) — to
**JSON / CSV** for external analysis.

XTB shut down its public xStation5 API on 2025-03-14. This tool instead reads
the data the xStation **web app already loads** in your logged-in browser
session, so there is no API key and no separate login.

## Security model

This is the whole point of the design:

- Runs **entirely in your browser** as a Chrome extension.
- It **never stores, exports, logs, or transmits** your session token, password,
  or any credential. Everything stays in the page.
- To label a capture with the right bucket (IKE / IKZE / main), it reads **only
  the `acn` (account-number) claim** from the request's bearer token, in memory,
  and immediately discards it. The account number is a public identifier shown
  throughout the xStation UI — not a secret — and the token itself (signature and
  all) is never retained. This is the only per-bucket signal XTB exposes: the
  gRPC requests have empty bodies and no account header.
- **Nothing is sent to any server.** Exports are generated locally and saved as
  files by you. No telemetry, no external endpoints, no `.env`, no secrets on
  disk.
- Fully open-source — read every line under `extension/src/`.

## How it works

The xStation web app fetches portfolio data from `ipax.xtb.com` over
**gRPC-Web** (binary protobuf). A `document_start` content script in the page's
MAIN world wraps `fetch`, tees the gRPC-Web response streams, and decodes the
protobuf **structurally** (no proprietary `.proto` needed). A small mapper names
the fields we care about; a floating panel lets you export JSON/CSV.

```
extension/
  manifest.json    MV3; `storage` permission (persists captures across account switches)
  src/decode.js    gRPC-Web frame parser + generic protobuf decoder (MAIN world)
  src/inject.js    fetch hook -> decode -> postMessage, tagged with active account (MAIN)
  src/mappers.js   field-number -> named fields (ISOLATED world)
  src/export.js    JSON/CSV builders (ISOLATED world)
  src/content.js   per-account store + auto-capture + popup bridge (ISOLATED, no page UI)
  popup.html/.js   toolbar popup — the only UI (summary + one-click capture/export)
  icons/           generated by scripts/generate-icons.js
```

### Buckets

Switching accounts in xStation reloads the app, so captures are persisted in
`chrome.storage.local` and merged on export. Positions are labelled by bucket:
**IKE**, **IKZE**, or **My Transactions** (single purchases). Investment plans
come from a separate stream that already spans accounts.

Exports:
- `xtb-portfolio-*.json` — full snapshot: a per-bucket + whole-portfolio
  `summary` (market value / cost / P&L), `positions` (each with instrument id,
  logo, average cost, and a `lots` array of individual purchase tranches — volume,
  open date, P&L per tranche), `balances`, `orders`, `retirementAccounts`, and
  `investmentPlans` (per plan: invested, current value, cash, P&L, created/updated
  dates; per holding: target %, units, price, cost, value, P&L).
- `xtb-positions-*.csv` — one row per position (bucket, symbol, volume, price,
  avgCost, marketValue, cost, netPL, plPct, swap, first/last open time).
- `xtb-plans-*.csv` — one row per plan holding.
- `xtb-history-*.csv` — value-over-time: one snapshot per day (kept locally on
  each capture), long format `date, bucket, value, marketValue, cost, netPL`
  (+ a `TOTAL` row per day; `value` = holdings + free cash). The JSON export
  includes the same `history`.

The mappers assert invariants (P&L = value − cost, equity = market value + free
funds, plan total = sum of plans). If XTB renumbers a protobuf field, the broken
invariant surfaces a **warning** in the popup instead of a silently-wrong export.

The UI is localized via `_locales` (English default, Polish included) and adapts
to the browser language; money is formatted in the account currency.

### Not yet captured

Closed positions, cash operations, and dividends are also on ipax gRPC
(`PortfolioClosedPositionService` / `PortfolioCashOperationService`), but the
terminal that requests them runs inside a **cross-origin iframe**
(`xcontainer.xtb.com`) the extension doesn't yet inject into. Finishing this
needs an extra host permission + iframe injection — see `BACKLOG.md`. XTB's
terminal has a native Export button for this data in the meantime.

## Install (unpacked)

1. Open `chrome://extensions`.
2. Enable **Developer mode** (top-right).
3. Click **Load unpacked** and select the `extension/` folder.
4. Open <https://xstation5.xtb.com/> and log in as usual.
5. Click the **toolbar icon** to open the popup, then **Capture portfolio** — the
   extension auto-navigates through every account and captures it.
6. Hit **JSON** / **Positions CSV** / **Plans CSV**.

The popup is the whole UI: it shows your total value, P&L, and a per-bucket
breakdown, then exports. Nothing is injected into the page.

## Status

Field maps calibrated live against the xStation UI (2026-07): retirement
accounts, positions (incl. signed P/L, purchase lots, open dates), investment
plans (holdings, cash, dates), account balances, and a computed portfolio
summary. Money is stored as signed 64-bit minor units (÷100); volume as a
protobuf `Decimal {unscaled, scale}`; timestamps as unix ms.

Buckets are attributed automatically via the token's `acn` account-number claim,
read in memory only — the token itself is never stored, exported, or transmitted.
